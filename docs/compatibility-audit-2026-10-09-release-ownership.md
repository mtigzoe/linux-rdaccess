# NVDA–Orca navigation release ownership audit

Base: `main` at `a7a2e6f1fa8d909dfe602ae4fd53aa3ae89550f7`.
Branch: `fix/nvda-orca-navigation-release-ownership`.

## Confirmed defects

1. A browse command retained its key-release ownership after an ordinary
   repeat. For example, a remote form-field or heading command followed by
   focus-mode typing allowed the repeated press into the application, then
   consumed its release. Layout, Find, Find Next, and table-edge commands had
   the same defect after the held modifiers changed.
2. Pass-next discarded old landmark and table-arrow release state, but retained
   state for form fields, headings, NVDA browse commands, and table edges. A
   bypassed repeat reached the application, yet its release could be swallowed
   if Orca processed it after the remote provenance token expired.

The keyboard hook now clears the previous release decision for the current
physical key when evaluating a press or repeat, before pass-next or navigation
can return early. An accepted command acquires release ownership again. A
mode or document change without an intervening press still preserves the
original command's release. Other physical keys keep their ownership.

The controller patch advances from v104 to v105 so existing installations
receive the changed hook. The upgrade retains the original private backup and
remains idempotent.

## Reproduction and validation

The regressions were run against the unchanged production generator first:
three test methods produced **11 failing subtests**. Six covered ordinary
repeats, five covered delayed pass-next releases, and the control case for a
release without a new press passed. The corrected generator passes them all.

| Focused check | Result |
| --- | --- |
| Browser command context, pass-next, controller upgrade | 37 passed |
| Legacy controller, historical upgrades, patch integrity, input trace, deferred Insert, direct commands, keypad layouts, input lifecycle | 403 passed |
| Speech lifecycle and native Say All callbacks | 32 passed |
| Disposable NVDA Remote TCP loopback | 22 passed |
| Genuine v104 generated by the saved original source, upgraded to v105 | Passed; backup preserved; repeat update was a no-op |
| Changed Python files compiled; `git diff --check` | Passed |

These runs used Python 3.10.12 and had no skips. The first loopback attempt
encountered 22 socket-permission errors in the network sandbox. The same
loopback suite passed when run with permission to open its disposable
`127.0.0.1` sockets. The 32 speech tests passed during the initial run.

## Limits

The new regressions execute the production patch generator with Orca fixtures
and controlled keyboard-event timing. Existing focused tests also execute
installed Orca gate/event-processor source. Loopback replaces external Orca
services and TLS. These results do not establish live Windows NVDA gesture
consumption, audible speech, physical braille behavior, or real application
key-release delivery. No active desktop, installed runtime, relay credentials,
or physical keyboard state was changed. The full suite and GUI acceptance
were not run for this focused input fix.

Later live acceptance should hold a browse-navigation key across a focus-mode
or modifier change, then verify application input receives a complete gesture.
Repeat the gesture with pass-next and a busy Orca main loop, and verify fresh
navigation and ordinary typing continue afterward.
