# NVDA–Orca Elements List held-key audit

Base: `main` at `287ea83`, containing PR #39.
Branch: `fix/elements-list-held-key-ownership`.

## Confirmed defect

When Orca's native structural-list API is unavailable, the NVDA Elements List
command falls back to injecting Alt+Shift+letter. The fallback checked held keys
using Windows VK identities only, although the receiver also supports name-only
keyboard events. A held `Shift_L`, `Alt_L`, or list shortcut letter could
therefore receive a synthetic press and release while the remote user still
held it. The controller retained the original event's release ownership even
though the Linux key was already physically up.

The new integration regression reproduced this using the patched controller,
the production XTest backend, and a disposable Xvfb server. `XQueryKeymap`
showed `m`, `M`, `Shift_L`, and `Alt_L` down before the fallback and up afterward.
This establishes an actual Linux input-state error rather than only extra
calls to a mocked backend. No active desktop was used.

## Fix

The fallback now compares resolved Linux key names alongside VK identities.
It borrows held name-only Shift/Alt keys and skips the shortcut when its letter
is already held. Uppercase and lowercase forms are checked because their
keysyms share the physical key on the tested X keyboard map. Normal shortcuts,
numeric/generic modifiers, unrelated held letters, cleanup after failed
synthetic releases, and the preferred native-list path retain coverage.

Controller v106 upgrades to v107 through the existing original-backup path.

## Focused validation

Before production changes, the new unit tests had 15 failing assertions,
including subtests, and the Xvfb regression had four. These all pass after the
fix.

| Check | Result |
| --- | --- |
| New structural-list ownership unit tests | 6 passed |
| Legacy controller, input ownership, chooser focus, native-list lifetime, patch integrity, historical upgrades, and braille protocol | 332 passed |
| XTest injection and backend ownership, under disposable Xvfb | 21 passed |
| Actual v106 output generated by the saved pre-change source, then upgraded to v107 | Passed; original backup and private modes preserved; repeat update was a no-op |
| Python 3.10 grammar, changed Python compilation, and whitespace checks | Passed |

All 359 focused test executions passed on Python 3.10.12, with zero skips.

## Limitations

The full suite, live Windows NVDA/Orca interaction, GUI acceptance, audible
speech, and physical braille devices were not tested. Xvfb proves Linux key
state and cleanup for the tested keyboard map, not end-to-end operation of an
Elements List dialog. Other keyboard layouts were not exercised. The defect
specifically concerns the supported name-only keyboard protocol and the
synthetic fallback used when the native structural-list API is unavailable.
