# Remote browse shortcut capture audit — 2026-10-09

## Confirmed defect

Orca 42's shortcut editor sets `orca_state.capturingKeys`. Its native
`KeyboardEvent.shouldConsume()` then returns `(False, 'Capturing keys')`
before looking up a binding or setting an event consumer. The bridge's browse
hooks ran before this gate: Find, layout, form fields, heading levels and table
edges could consume captured keys. This also swallowed NVDA modifier commands
outside document content, where a preferences dialog normally runs.

Landmark and table-arrow translation reached the native gate, but first
rewrote the event, queried bindings and recorded release ownership. A release
from an earlier browse command could also be consumed after capture started.
Already queued browse consumers had no capture check and could still execute.

The eight new regression methods were run against genuine controller output
generated by main commit `180fabd` (v109). They produced 51 failing assertions
across their subtests, with no errors or skips. The reference dispatcher is an
unmodified frozen Orca 42 method; its AST matches the installed native method.

## Fix

Consume only the matching, eligible remote injection claim during capture,
then leave the key unchanged for Orca's native dispatcher. Retiring that claim
prevents it from translating a later local key. Earlier keys with an ineligible
chord retain the pending remote claim until its actual key arrives.

If capture starts while a translated key is held, clear that key's previous
release ownership and let the native dispatcher evaluate the release. Browse
consumers also check capture at invocation, so queued navigation does not run
while the editor owns keyboard input. New remote commands work after capture
ends.

The generated controller advances from v109 to v110. The original upstream
backup remains the source for updates. Root-level Python compatibility wrappers
are unchanged. The regression module is already part of the existing GitHub
Actions `keyboard-and-browse` matrix entry; no matrix changes are needed.

## Limits

The tests exercise generated bridge code and the native dispatcher method with
simulated Orca scripts and input. Live Windows NVDA, the actual Orca preferences
dialog, application acceptance, audible speech and physical braille were not
tested. Xvfb and full repository discovery were not run for this change.
The guard covers KeyboardEvent browse translation and suppression; input-help
presentation and direct script-command paths were not changed.

Existing installations need the normal connect/update flow and an Orca restart
to load the updated controller and hook. No real user configuration was changed.
GitHub Actions were not monitored or awaited, and the PR was not merged.
