# NVDA Remote compatibility fixes, October 6, 2026

Claude's `table-nav-ctrl-alt-arrow-v37.patch` and `bugfixes-v38.patch` were
already applied at commit `92df2d8`. This follow-up advances the controller to
v40 and updates the Orca runtime adapter. The local-machine patch stays at v10.
Development and verification use local code, tests and Linux runtime checks;
no Desktop Commander calls are needed for this work.

## Concrete defects and changes

- Table/landmark bursts: one timestamp could represent only the latest pending
  remote key. Several keys arriving before Orca processed them lost earlier
  translations. Each injected key now publishes a bounded, expiring claim;
  arrows match their own key name and repeated presses retain separate claims.
  An earlier plain arrow or Ctrl+D cannot consume a later eligible gesture's
  claim before its modifiers have been checked.
  Backend failure removes the exact claim, and reconnect/reset clears claims.
- Manual browse/focus switching: passing `None` to Orca 42's
  `togglePresentationMode` selected its automatic-switch branch. It could
  announce focus mode without focusing the current editor. The adapter and
  legacy fallback now supply a truthy manual keyboard event. A test exercises
  the method extracted from the installed Orca 42 source and checks editor focus.
- Duplicate native commands: a supported handler returning `False` was treated
  as unsupported and could run again through fallback. Adapter results now
  distinguish unsupported (`None`), declined (`False`) and completed (`True`).
  Invocation errors, including `ImportError` after partial work, do not retry
  commands, structural lists or the elements chooser. Import/API absence still
  allows the verified legacy fallback.
- Clock/caret conflict: raw NVDA+F12 reached Orca+F12, which toggles caret
  navigation. The bridge now calls `presentTime`; a second complete gesture
  within 0.5 seconds calls `presentDate`. Autorepeat is consumed. Queued
  callbacks retain their own time/date choice, and intervening actions or a new
  control generation reset the repeat count. Plain and Ctrl+F12 still reach
  the application.
- Current-line command: desktop NVDA+Up now calls native `sayLine` using Orca's
  caret context or focused object. Focus outside document content takes
  precedence over a stale page caret, including Firefox's address bar.
  It neither enters flat review nor moves the
  caret. Plain Up, keypad Up and modified application shortcuts retain their
  native handling.
- Automatic reconnect: the customization started a one-shot `transport.run`
  thread, so an unavailable relay at startup ended automatic connection attempts.
  It now starts the transport's existing retry worker once. Native disconnect
  stops retries and manual reconnect replaces the worker. The patch recognizes
  the verified upstream startup block and refuses ambiguous modifications;
  `doctor` checks the actual patched block. It does not change the upstream
  transport's handling of cancellation during a connection already in progress.

## Verification and scope

Regression tests cover queued and repeated table/landmark keys, key-specific
claims, backend rejection/exception rollback, mode gates, modifier/key-release
ownership, manual editor focus, explicit decline and partial-failure dispatch,
clock gesture timing, queued commands and current-line caret selection. A frozen
controller generated by the actual v38 source tests private, idempotent upgrade
to v40, alongside earlier upgrade fixtures and the intermediate v39 installed
during this audit. Tests also parse target code with
Python 3.10 grammar for Linux Mint compatibility.

These changes do not establish full NVDA parity. Laptop-layout shortcuts,
object/review navigation, current-line spelling/details, first/last table
row/column commands and application-specific behavior still need work. Table
arrows can be intercepted by desktop workspace shortcuts before Orca sees
them. XTest cannot distinguish a simultaneous local press of the same key from
a pending remote claim. Windows NVDA speech and live Firefox navigation need a
separate controlled end-to-end check.

The complete suite passed with 635 tests using
`xvfb-run -a /usr/bin/python3 -m unittest discover -s tests`, including X11 lock
and real Orca key-matching checks on an isolated display. A separate 69-test
adapter/direct-command/upgrade/reconnect run passed with the default Python interpreter.
The updated `tools/orca42_d_landmark_check.py` also passed on a dedicated
Xvfb/D-Bus session with the installed Orca 42 key matcher and synthetic
controller input; it asserts handlers and restored hardware/modifier state.

Controller v40, local-machine v10, the native-event and automatic-reconnect
customization patches, and the updated adapter were installed on Mint.
`doctor` reports all five checks current. A temporary metadata-only startup
probe confirmed loaded controller/transport objects, the event API helper and
navigation hook, and a running native retry worker. There was one Orca process.
The configured relay refused a scoped TCP connection and Orca remained
disconnected; no live Windows NVDA/Firefox result is claimed. Orca was then
restarted normally without the temporary probe, leaving retries enabled.

The native NVDA clock gesture and repeat behavior were checked against
[NVDA's release-2026.2 global commands](https://github.com/nvaccess/nvda/blob/release-2026.2/source/globalCommands.py).
Orca command signatures and manual-mode behavior were checked against the
installed `/usr/lib/python3/dist-packages/orca` source.
