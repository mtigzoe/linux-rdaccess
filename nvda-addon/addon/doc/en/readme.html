Linux Remote Access Companion

This development add-on runs inside Windows NVDA. It presents Linux semantic braille received through NVDA Remote Access and provides opt-in local testing. NVDA Remote Access remains responsible for the connection, speech and keyboard control. This add-on does not include RDP or Citrix drivers.

Migration

A RDAccess development build may already contain this Linux integration. Disable that build through NVDA's add-on manager before enabling the companion, or use a RDAccess version without the Linux integration. The companion stays inactive while a running RDAccess plugin provides the same bridge. Disabling RDAccess also disables its RDP/Citrix functionality until it is re-enabled.

Installing or restarting NVDA during agent-assisted work requires explicit user authorization. Installation does not carry over test consent.

Authorize testing

Connect Remote Access as “Control another computer” using your existing settings. In NVDA Tools choose “Authorize Linux test session...”. Connection permission is unchecked by default. Choose “Authorize for five minutes”. From the linux-rdaccess repository, run python linux_rdaccess_test_session.py start-all.

Only status, connection using saved settings, and cancellation of a connection created by this consent session are supported. Keyboard, clipboard and arbitrary code operations are unavailable. Existing connections are preserved. Choose “Revoke Linux test session” to end authorization immediately. Consent also ends on expiry, lock, secure desktop, configuration profile switch or NVDA shutdown.

Validation limits

Build 20261013.0.4 addresses a reproduced case where dismissing a Linux status message could return braille to Windows content instead of Linux. It is automated-tested; installation and physical message-restoration acceptance remain pending.

Build 20261013.0.3 addresses a reproduced case where routing could use stale text information and fail to move the Linux caret. It is automated-tested; installation and physical routing/caret acceptance remain pending.

Automated regressions and Windows kernel tests do not prove audible speech or physical braille output. Build 20261013.0.2 is installed and active; its 13 Python files match the tested build. Earlier Firefox input and physical panning observations were limited. A later left-pan test on build .1 with a Eurobraille b.note still showed Windows application context. Build .2 corrects reproduced BrailleExtender focus-context and pan-script interactions. After reinstalling build .2, the user confirmed Linux content after physical left pan in both Firefox and the Linux terminal. This limited physical PASS does not establish repeated/boundary panning, routing, caret tracking or complete end-to-end acceptance.

NVDA formats semantic braille. Speech currently forwards Orca-generated wording, including role names such as “push button”. NVDA-style semantic speech and the reported Tab/Shift+Tab announcement difference remain unverified.
