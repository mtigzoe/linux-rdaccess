Linux Remote Access Companion

This development add-on runs inside Windows NVDA. It presents Linux semantic braille received through NVDA Remote Access and provides opt-in local testing. NVDA Remote Access remains responsible for the connection, speech and keyboard control. This add-on does not include RDP or Citrix drivers.

Migration

A RDAccess development build may already contain this Linux integration. Disable that build through NVDA's add-on manager before enabling the companion, or use a RDAccess version without the Linux integration. The companion stays inactive while a running RDAccess plugin provides the same bridge. Disabling RDAccess also disables its RDP/Citrix functionality until it is re-enabled.

Installing or restarting NVDA during agent-assisted work requires explicit user authorization. Installation does not carry over test consent.

Authorize testing

Connect Remote Access as “Control another computer” using your existing settings. In NVDA Tools choose “Authorize Linux test session...”. Connection permission is unchecked by default. Choose “Authorize for five minutes”. From the linux-rdaccess repository, run python linux_rdaccess_test_session.py start-all.

Supported operations are status, optionally selected numeric routing diagnostics, connection using saved settings, and cancellation of a connection created by this consent session are supported. Keyboard, clipboard and arbitrary code operations are unavailable. Existing connections are preserved. Choose “Revoke Linux test session” to end authorization immediately. Consent also ends on expiry, lock, secure desktop, configuration profile switch or NVDA shutdown.

Build 20261013.0.6 adds the unchecked option “Record numeric braille routing diagnostics (no text)” to the authorization dialog. It collects at most twelve in-memory routing/message events during that session and clears them when authorization ends. Text, object/gesture identifiers and ordinary typing are not recorded. Read the trace with python linux_rdaccess_test_session.py nvda-braille-trace. Collection requires the checkbox; the read command cannot enable it.

Build 20261014.0.1 adds a separate outcome ledger, read with python linux_rdaccess_test_session.py nvda-braille-outcomes. The same unchecked diagnostics option enables both ledgers, each limited to twelve records with independent dropped counts. Both clear when consent ends. Version 1 and 2 operations remain unchanged; the outcome read uses version 3. An activation/caret attempt or a successful send call does not establish a Linux caret movement. Unknown/custom routing remains explicitly unknown.

Validation limits

Build 20261014.0.3 discards queued native document-routing presses if the original Linux snapshot, control activation, connection, braille handler or visible buffer changes before execution. Fresh presses retain native NVDA input help, capture and script behavior. This correction is automated-tested; physical routing and the historical 6-to-9 caret movement remain unverified. This review candidate is based on merged main and does not include unmerged PR #89's separate one-shot automation. It has not been installed.

Build 20261014.0.1 adds diagnostics without changing routing policy. It is prepared for review and has not been installed or physically tested. The user previously installed .6; its fourteen Python files matched disk. Its mixed routing trace does not establish physical message acceptance.

Build 20261013.0.6 retained the .5 queued-message routing fix and added automated-tested diagnostics. The user installed .5; its thirteen packaged Python files matched the installed files. A later two-press message check reported line restoration but recorded Linux caret movement from 20 to 7. The exact cause, including the earlier .4 movement from 6 to 9, remains unconfirmed. The new trace is intended to distinguish message ownership, Remote Access dismissal, and outgoing semantic caret requests.

Build 20261013.0.5 prevents a routing press made on a Linux status message from moving the Linux caret if that message expires before the queued command executes. This race is automated-reproduced and tested. The physical caret-preservation check remains unresolved despite user installation of .5.

Build 20261013.0.4 addresses a reproduced case where dismissing a Linux status message could return braille to Windows content instead of Linux. The user confirmed message appearance and timeout restoration in Mousepad. Linux caret preservation during routing dismissal and broader physical message acceptance remain unresolved.

Build 20261013.0.3 addresses a reproduced case where routing could use stale text information and fail to move the Linux caret. It is automated-tested; installation and physical routing/caret acceptance remain pending.

Automated regressions and Windows kernel tests do not prove audible speech or physical braille output. An earlier installation of build 20261013.0.2 had all 13 Python files matching the tested build. Earlier Firefox input and physical panning observations were limited. A later left-pan test on build .1 with a Eurobraille b.note still showed Windows application context. Build .2 corrects reproduced BrailleExtender focus-context and pan-script interactions. After reinstalling build .2, the user confirmed Linux content after physical left pan in both Firefox and the Linux terminal. This limited physical PASS does not establish repeated/boundary panning, routing, caret tracking or complete end-to-end acceptance.

NVDA formats semantic braille. Speech currently forwards Orca-generated wording, including role names such as “push button”. NVDA-style semantic speech and the reported Tab/Shift+Tab announcement difference remain unverified.
